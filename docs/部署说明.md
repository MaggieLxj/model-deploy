## 二、服务部署详情

### 2.1 DeepSeek V4 Flash

**模型信息**
- 模型类型: DeepseekV4ForCausalLM
- 架构: MoE (Mixture of Experts)，256 个路由专家 + 1 个共享专家
- 隐藏层维度: 4096
- 层数: 43
- 注意力头数: 64
- KV 头数: 1 (MQA)
- 词表大小: 129280
- 最大位置编码: 1048576 (1M)
- 量化: FP8 权重量化 (e4m3, dynamic activation)
- 模型文件: 46 分片 safetensors，共 149 GB

**推理框架**: vLLM (自定义镜像 `custom-vllm-deepseek`)

**部署配置要点**
- 基础镜像: `vllm/vllm-openai:v0.22.1`，额外安装 `nvidia-cutlass-dsl[cu13]==4.5.0`
- 网络模式: `host`（直接使用主机网络）
- GPU: CUDA_VISIBLE_DEVICES=4,5,6,7 (4卡)
- Tensor 并行: 4
- KV Cache 数据类型: FP8
- Block Size: 256
- GPU 显存利用率: 0.9
- 最大模型长度: 384000 (384K)
- 共享内存: 64 GB
- 端口: 9996
- 特殊配置:
  - `--tokenizer-mode deepseek_v4` — DeepSeek V4 专用 tokenizer
  - `--tool-call-parser deepseek_v4` — 工具调用解析
  - `--reasoning-parser deepseek_v4` — 推理输出解析
  - `--enable-expert-parallel` — 启用专家并行
  - `--compilation-config` — CUDA Graph 全量+分段编译

**资源占用（实测运行中）**
- GPU 显存: 每卡约 78.3 GB / 80 GB（占用率 ~96%）
- 系统内存: 约 21.4 GB
- 生成吞吐: 约 8.4 tokens/s（单请求）
- KV Cache 利用率: 约 1.1%
- Prefix Cache 命中率: 89%-95%

### 2.2 GLM-5.1 (GGUF)

**模型信息**
- 模型类型: GLM-5.1 (GGUF 量化格式)
- 量化方式: UD-Q2_K_XL（超低比特量化）
- 模型文件: 7 分片 GGUF，共 236 GB
- 目录: `./GLM-5.1-GGUF/UD-Q2_K_XL`

**推理框架**: llama.cpp (`ghcr.io/ggml-org/llama.cpp:full-cuda`)

**部署配置要点**
- 网络模式: `host`
- GPU: CUDA_VISIBLE_DEVICES=4,5,6,7 (4卡)
- GPU 层数: 99 (全部加载到 GPU)
- 并行度: 2
- Tensor Split: 4,4,4,4 (均匀分配到 4 卡)
- 上下文长度: 405504 (约 405K)
- Batch Size: 2048
- 线程数: 32
- 端口: 9996
- 共享内存: `/dev/shm` 挂载

**资源占用（估算）**
- GPU 显存: 每卡约 59 GB（236 GB / 4 卡）
- 系统内存: 较低（模型全量在 GPU 上）

### 2.3 MiniMax M2.7 (GGUF)

**模型信息**
- 模型类型: MiniMax-M2.7 (GGUF 量化格式)
- 量化方式: UD-IQ4_XS（中等量化，约 4-bit）
- 模型文件: 4 分片 GGUF，共 101 GB
- 目录: `./MiniMax-M2.7-GGUF/UD-IQ4_XS`

**推理框架**: llama.cpp (`ghcr.io/ggml-org/llama.cpp:full-cuda`)

**部署配置要点**
- 网络模式: `host`
- GPU: CUDA_VISIBLE_DEVICES=2,3 (2卡)
- GPU 层数: 99 (全部加载到 GPU)
- 并行度: 1
- Tensor Split: 4,4 (均匀分配到 2 卡)
- 上下文长度: 196608 (约 196K)
- Batch Size: 1024
- 线程数: 16
- 端口: 9996
- 共享内存: `/dev/shm` 挂载

**资源占用（估算）**
- GPU 显存: 每卡约 50.5 GB（101 GB / 2 卡）
- 系统内存: 较低

---

### 2.4 Qwen 3.6 27B

**模型信息**
- 模型类型: Qwen3_5ForConditionalGeneration (多模态)
- 隐藏层维度: 5120
- 层数: 64
- 注意力头数: 24
- KV 头数: 4 (GQA)
- 词表大小: 248320
- 最大位置编码: 262144 (262K)
- 精度: BF16 (无权重量化)
- 模型文件: 15 分片 safetensors，共 52 GB

**推理框架**: vLLM (官方镜像 `vllm/vllm-openai:v0.22.1`)

**部署配置要点**
- 网络模式: `host`
- GPU: CUDA_VISIBLE_DEVICES=7 (1卡)
- Tensor 并行: 1
- KV Cache 数据类型: FP8
- GPU 显存利用率: 0.90
- 最大模型长度: 262144 (262K)
- 端口: 9993
- 特殊配置:
  - `--tool-call-parser qwen3_coder` — Qwen3 代码工具调用
  - `--reasoning-parser qwen3` — Qwen3 推理解析
  - `--trust-remote-code` — 信任远程代码
  - `--enforce-eager` — 禁用 CUDA Graph (eager 模式)
  - `HF_HUB_OFFLINE=1` — 禁止在线下载

**资源占用（估算）**
- GPU 显存: 约 50-55 GB / 80 GB（52GB 模型 + KV Cache）
- 系统内存: 较低

## 三、GPU 分配总览

```
GPU 0  [空闲]          ┐
GPU 1  [空闲]          ├─ 可用于其他任务
                       ┘
GPU 2  [MiniMax]       ┐
GPU 3  [MiniMax]       ├─ MiniMax M2.7 (2卡)
                       ┘
GPU 4  [DeepSeek/GLM5] ┐
GPU 5  [DeepSeek/GLM5] ├─ DeepSeek V4 或 GLM-5.1 (4卡，互斥)
GPU 6  [DeepSeek/GLM5] │
GPU 7  [DeepSeek/GLM5/ ├─ Qwen 3.6 27B 也可使用此卡
        Qwen]          ┘
```

### 互斥关系

| 冲突组 | 服务 | 原因 |
|--------|------|------|
| 组 1 | DeepSeek V4 / GLM-5.1 | 共用 GPU 4-7，不可同时运行 |
| 组 2 | DeepSeek/GLM + Qwen | Qwen 使用 GPU 7，与 DeepSeek/GLM 冲突 |

**推荐组合**:
- DeepSeek + MiniMax (GPU 2-3 给 MiniMax, GPU 4-7 给 DeepSeek)
- GLM-5 + MiniMax + Qwen (GPU 2-3 给 MiniMax, GPU 4-6 给 GLM-5 部分, GPU 7 给 Qwen — 需注意 GLM-5 的 tensor-split 需调整)
- Qwen + MiniMax (GPU 2-3 给 MiniMax, GPU 7 给 Qwen)

## 六、推理框架对比

| 特性 | vLLM | llama.cpp |
|------|------|-----------|
| 适用模型 | DeepSeek V4, Qwen 3.6 | GLM-5.1, MiniMax M2.7 |
| 镜像 | `custom-vllm-deepseek` / `vllm/vllm-openai` | `ghcr.io/ggml-org/llama.cpp:full-cuda` |

| 模型格式 | safetensors / HF 格式 | GGUF |

## 七、运维脚本

### 启动服务 (`start-model.sh`)

```bash
./start-model.sh deepseek   # 启动 DeepSeek V4 Flash
./start-model.sh glm5       # 启动 GLM-5.1 GGUF
./start-model.sh minimax    # 启动 MiniMax M2.7 GGUF
./start-model.sh qwen       # 启动 Qwen 3.6 27B
```

脚本会自动检查:
1. Docker 和 Docker Compose 是否安装
2. GPU 是否可用
3. 模型文件是否存在
4. 服务是否启动成功

### 停止服务 (`stop-model.sh`)

```bash
./stop-model.sh deepseek   # 停止 DeepSeek
./stop-model.sh glm5       # 停止 GLM-5.1
./stop-model.sh minimax    # 停止 MiniMax
./stop-model.sh qwen       # 停止 Qwen
./stop-model.sh            # 停止所有服务
```

### 查看日志

```bash
docker logs vllm-ds4-server           # DeepSeek 日志
docker logs glm5-llama-server         # GLM-5 日志
docker logs minimax27-llama-server    # MiniMax 日志
docker logs qwen36-server             # Qwen 日志
```

## 八、常见问题

### Q1: 启动 DeepSeek 失败，提示 CUDA OOM
**原因**: GPU 显存不足或被其他服务占用。
**解决**: 确保停止 GLM-5.1 和 Qwen 服务后再启动 DeepSeek。

### Q2: 端口 9996 被占用
**原因**: 同一端口上有其他服务运行。
**解决**: 先停止占用端口的服务，或修改 `docker-compose.*.yaml` 中的端口号。

### Q3: 模型加载时间过长
**原因**: 模型文件较大（DeepSeek 149GB, GLM 236GB），首次加载需要读取全部权重。
**解决**: 正常现象，耐心等待。DeepSeek 约 5-10 分钟加载完成。

### Q4: Qwen 与 DeepSeek 能否同时运行？
**不能**。两者都使用 GPU 7，存在冲突。需先停止 DeepSeek 再启动 Qwen，反之亦然。

### Q5: 如何切换 DeepSeek 和 GLM-5.1？
```bash
./stop-model.sh deepseek    # 先停止 DeepSeek
./start-model.sh glm5       # 再启动 GLM-5.1
```
